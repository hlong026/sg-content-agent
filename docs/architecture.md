## 二、Hermes 核心引擎

Hermes 是中央决策引擎，负责感知-推理-规划-执行-反思-进化的完整循环。

### 2.1 主循环

```
感知(perceive) → 推理(reason) → 规划(plan) → 执行(execute) → 反思(reflect) → 进化(evolve)
      ↑                                                                    │
      └────────────────────────────────────────────────────────────────────┘
```

### 2.2 感知器 (Perceiver)

从环境中收集信号：

| 信号类型 | 来源 | 频率 |
|---------|------|------|
| 定时信号 | Cron 调度器 | 每日/每周 |
| 事件信号 | 热点爆发、竞品发布、政策变动 | 实时 |
| 反馈信号 | 内容互动数据回收 | 每4小时 |
| 异常信号 | 发布失败、评分过低 | 即时 |

### 2.3 规划器 (Planner)

将决策分解为可执行的 Skill 组合序列，处理依赖关系和并行编排。

### 2.4 反思器 (Reflector)

评估执行结果，提取经验教训，生成改进建议。

### 2.5 进化引擎 (Evolution Engine)

三层进化模型：

```
Layer 1: 参数进化（自动，高频）
  ├── Skill 参数调优（权重、阈值、温度等）
  ├── Prompt 模板进化
  └── 发布时间优化

Layer 2: 策略进化（半自动，中频）
  ├── 选题策略调整
  ├── 内容结构模板更新
  ├── 平台运营策略迭代
  └── 风格参数微调

Layer 3: 能力进化（需要审核，低频）
  ├── 新 Skill 生成
  ├── Skill 组合发现（新工作流）
  ├── 知识图谱扩展
  └── 新平台接入
```

## 四、记忆系统

```
Memory Store
├── 短期记忆 (Working Memory) — 最近 7 天
│   ├── 本周选题计划及执行状态
│   ├── 最近发布的内容及其表现
│   ├── 当前热点话题
│   └── 待处理的通知和异常
│
├── 长期记忆 (Long-term Memory) — 全量历史
│   ├── 所有发布内容 + 表现数据（向量检索）
│   ├── 博主风格画像（定期更新版本）
│   ├── 知识库全量数据
│   ├── 竞品历史数据
│   └── 赛道趋势历史
│
├── 经验记忆 (Episodic Memory) — 进化的核心
│   ├── 经验三元组：(决策, 行动, 结果)
│   ├── 反思日志
│   ├── 进化日志
│   ├── A/B 测试结果
│   └── 表现规则库
│
└── 过程记忆 (Procedural Memory) — 技能知识
    ├── 各 Skill 的最优 Prompt 模板版本
    ├── 各 Skill 的最优参数配置
    ├── Skill 组合的最佳实践
    └── 平台特性的隐性知识
```

## 六、选题评分模型

```
选题得分 = f(时效性, 热度趋势, 竞品表现, 历史数据匹配度, 差异化空间)

┌────────────┬──────┬──────────────────────────────────┐
│    因子     │ 权重  │           计算方式                │
├────────────┼──────┼──────────────────────────────────┤
│ 时效性      │ 20%  │ 话题热度随时间的衰减曲线           │
│ 热度趋势    │ 25%  │ 搜索指数变化率 + 平台推荐权重      │
│ 竞品表现    │ 20%  │ 同类选题在竞品账号的平均互动率     │
│ 历史匹配    │ 20%  │ 该博主在同类选题的历史爆款概率     │
│ 差异化空间  │ 15%  │ 该选题的未饱和度（蓝海程度）       │
└────────────┴──────┴──────────────────────────────────┘
```

## 七、博主风格克隆引擎

### 7.1 风格画像维度

| 维度 | 分析内容 |
|------|---------|
| 语言风格 | 口语化程度、专业术语使用频率、语气词偏好 |
| 叙事结构 | 开头方式、段落节奏、结尾习惯 |
| 内容偏好 | 数据对比频率、清单体使用、个人经历引用 |
| 视觉风格 | emoji使用、排版偏好、标题范式 |
| 情感基调 | 鼓励型/中立型/犀利型/温暖型 |
| 平台适配 | 不同平台的差异化风格 |

### 7.2 风格校准流程

```
生成内容 → 风格画像对比 → 差异计算 → LLM修正 → 再次对比 → 通过/打回
```

## 八、质量评分系统

```
┌─────────────┬─────┬──────────────────────────────────────┐
│    维度      │ 分值 │              评判标准                  │
├─────────────┼─────┼──────────────────────────────────────┤
│ 风格匹配度   │ 25  │ 与博主历史内容的风格相似度              │
│ 事实准确性   │ 20  │ 关键数据是否与知识库一致               │
│ 可读性      │ 15  │ 段落长度、逻辑流畅度                   │
│ 互动潜力    │ 15  │ 是否有互动引导、是否有争议点/共鸣点      │
│ SEO 友好度  │ 10  │ 关键词密度、标签合理性                  │
│ 差异化      │ 15  │ 与竞品同类内容的区分度                  │
└─────────────┴─────┴──────────────────────────────────────┘

→ 得分 ≥ 80 分：自动进入发布队列
→ 得分 60-80 分：人工审核
→ 得分 < 60 分：自动重生成（最多3次）
```

```
    ┌──────────┐  发布  ┌──────────┐  数据回收  ┌──────────┐
    │  内容生成  │─────→│  各平台    │─────────→│  效果分析  │
    └──────────┘      └──────────┘          └──────────┘
          ▲                                          │

反馈维度：
├── 互动率（点赞/收藏/评论/转发 ÷ 曝光量）
├── 完读率/完播率
├── 涨粉效率

├── 发布时间 × 互动率 → 优化发布时间
└── 风格要素 × 互动率 → 优化风格参数
```
