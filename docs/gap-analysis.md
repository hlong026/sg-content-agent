# 真实业务可用性分析报告

## 一、结论

**当前状态：功能演示级（Demo），不是生产可用工具。**

框架搭好了，全链路能跑通，但距离真实博主每天使用，有 7 个关键缺口。

---

## 二、7 个关键问题

### 🔴 P0：不接真实 LLM = 所有生成内容是假的

**现状**：没有配置 API Key 时，LLM Client 返回硬编码的 Mock 文本。
Mock 生成的内容实际上是 JSON 格式的选题列表文本，不是正文。

**问题**：
- 调用 `generateContent` 返回的 body 是 `[{"title":"NUS CS..."}]` 这种 JSON 字符串
- 不是小红书风格的正文内容
- 质量评分全部为 null

**修复**：至少需要配置一个 OpenAI 兼容的 API。

---

### 🔴 P0：没有真实采集能力

**现状**：采集数据全部靠手动录入的种子数据。
没有 Playwright 爬虫、没有 API 对接、没有定时采集。

**问题**：
- 无法自动采集博主自己的小红书内容
- 无法自动采集竞品内容
- 无法获取实时热点数据
- 「数据采集」页面只能手动添加

---

### 🔴 P0：没有真实发布能力

**现状**：发布只是改了数据库状态。没有 Playwright RPA，没有对接小红书创作者中心。

**问题**：
- 无法真正发布到小红书
- 无法上传图片
- 无法填写标签
- 整个"发布"只是状态流转

---

### 🟡 P1：内容生成 Prompt 不够精细

**现状**：Prompt 模板是通用的，没有按内容类型区分。

**问题**：
- 「院校介绍」和「租房攻略」用同一个 Prompt 模板
- 没有长度控制（Mock 只生成 442 字，真实应该 800-1200 字）
- 标签生成过于简单
- 没有候选标题的差异化策略

---

### 🟡 P1：知识库数据量不够

**现状**：14 条知识，覆盖面太窄。

**问题**：
- 院校只有 NUS/NTU/SMU 三个
- 没有具体专业学费数据
- 没有录取案例
- 真实使用需要 200-500 条知识

---

### 🟡 P1：没有定时任务

**现状**：所有操作都需要手动触发。

**问题**：
- 没有每日自动采集
- 没有每周自动推荐选题
- 没有自动回收互动数据
- 没有"无人值守"能力

---

### 🟢 P2：前端体验粗糙

**现状**：功能能用，但体验不成熟。

**问题**：
- 没有加载骨架屏
- 没有操作反馈动画
- 移动端未适配
- 没有数据图表（只有数字）
- 编辑器是纯文本，没有富文本预览

---

## 三、修复优先级

```
真正可用的最小路径：

  1. 接入真实 LLM API          ← 最关键，1 天
  2. 修复 Mock 返回格式问题      ← 1 天
  3. 按内容类型做 Prompt 模板    ← 2 天
  4. 小红书 RPA 发布            ← 3 天
  5. 小红书 RPA 采集            ← 3 天
  6. 定时任务调度               ← 2 天
  7. 知识库扩充到 100+ 条       ← 1 天（可用 LLM 批量生成）
  8. 前端体验打磨               ← 3 天

总计：约 16 个工作日
```
